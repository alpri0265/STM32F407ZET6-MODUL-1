# Аналіз: чому енкодер з кнопкою працював некоректно

## Що перевірено і виправлено

### 1. **Втрата кроків енкодера (виправлено)**

**Проблема:** У `encoder_menu.c` був ранній вихід:
```c
if (encoder_menu_get_action() != ENCODER_MENU_ACTION_NONE)
    return;
```
Далі йшов виклик `enc_if_take_encoder_step()`. Якщо екран ще не встиг обробити попередню дію (CW/CCW), `action` залишався встановленим, функція одразу виходила і **не викликала** `enc_if_take_encoder_step()`. Нові кроки з TIM6 ISR накопичувались в `enc_pending`, але ніхто їх не забирав, тому обертання виглядало як «не реагує» або «пропускає» кроки.

**Виправлення:** Кроки з ISR тепер завжди забираються на початку `encoder_menu_process()` (без раннього return перед `take_encoder_step`).

---

### 2. **Гонка при читанні/скиданні enc_pending (виправлено)**

**Проблема:** У `enc_if_take_encoder_step()` робилось:
```c
int v = enc_pending;
enc_pending = 0;
return v;
```
Між читанням і записом мог спрацювати TIM6 і знову встановити `enc_pending`. Потім запис `enc_pending = 0` міг обнулити цей новий крок — один крок міг втрачатись.

**Виправлення:** Читання і скидання `enc_pending` виконуються в короткій критичній секції (`__disable_irq()` / `__enable_irq()`).

---

### 3. **Що залишилось без змін (перевірено)**

- **Полярність кнопки:** `enc_if_btn_raw()` = true при GPIO low (натиснуто). Для KEY→GND з підтяжкою вгору — коректно.
- **Піни:** PB12 (A), PB13 (B), PB14 (KEY) — у `main.h` і в MX_GPIO_Init задані правильно (INPUT pull-up для B і KEY, EXTI для A не використовується для логіки, тільки для a_pending).
- **TIM6:** Запускається до `app_init()`; `enc_if_init_encoder_state()` викликається в `encoder_menu_init()` і переініціалізує стан енкодера — після цього логіка узгоджена.
- **Один крок за раз:** В ISR зберігається лише один pending крок (1=CW, 2=CCW). При дуже швидкому обертанні можуть «зливатись» кілька кліків в один крок — це свідома обмеження для спрощення та стабільності.

---

## Що перевірити на платі

1. **Підключення:** S1→PB12, S2→PB13, KEY→PB14, GND спільний. Для 5 V модуля — дільники 2k2/3k3 на S1, S2, KEY.
2. **Якщо напрямок обертання навпаки:** у `bsp/enc_if.c` поміняти місцями масиви `enc_cw_next` та `enc_ccw_next` (або міняти обробку CW/CCW у `screens.c`).
3. **Якщо кнопка не реагує:** перевірити, що KEY при натисканні дає 0 V (low); якщо у вас активний high — потрібно інвертувати логіку в `enc_if_btn_raw()`.

---

## Потік даних (для налагодження)

```
TIM6 1 ms → enc_if_poll_1ms() → валідний перехід (A,B) → enc_pending = 1 або 2
    ↓
events_process() → encoder_menu_process() → enc_if_take_encoder_step() → action = CW/CCW
    ↓
screens_process() → encoder_menu_get_action() → menu_select_next/prev(), encoder_menu_clear_action(), render_menu()
```

Кнопка: кожен цикл `encoder_menu_process()` викликає `poll_button()`; при фронті натискання (з дебаунсом 30 мс) встановлюється `action = ENTER`.
